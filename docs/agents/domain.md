# Domain docs

This repository uses a single domain context.

## Before exploring

- Read the root `GLOSSARY.md`.
- Read relevant existing ADRs under `docs/adr/`.
- If a document does not exist, proceed without creating a placeholder.

## Vocabulary and decisions

Use glossary terms consistently in specs, issues, and test names.
Record newly agreed terms through domain modeling.
Surface conflicts with existing ADRs instead of silently overriding them.

Create glossary entries and ADRs only when an actual term or
qualifying architectural decision needs recording.
